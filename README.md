# Recommendation System – End-to-End Data Management Pipeline

**Course:** Data Management for Machine Learning – Assignment 2
**Student:** Mohammad Saqib Rahman | **ID:** 2025AG05257

A modular pipeline on a **synthetic online-bookstore dataset** (users, books, ratings):
Ingestion → Validation → Preparation → Transformation → Features → Training → Evaluation,
orchestrated with **Prefect** and tracked with **MLflow**.

## Project structure
```
recommendation-pipeline/
├── configs/config.yaml        # all settings (paths, K, split, MLflow)
├── dags/recommendation_flow.py# Prefect workflow
├── src/                       # one module per stage (ingestion ... evaluation)
├── data/{raw,processed,features,errors}
├── models/                    # saved models
├── reports/                   # validation report, feature catalog, model results
├── run_pipeline.py            # same pipeline without Prefect (supports --stage)
├── tests/                     # small unit tests
└── requirements.txt
```

## Setup (Python 3.10+)
```bash
python -m venv venv
venv\Scripts\activate          # Windows   (Mac/Linux: source venv/bin/activate)
pip install -r requirements.txt
```

## Run
Option A – plain Python (no server needed):
```bash
python run_pipeline.py
```
Option B – Prefect workflow with UI:
```bash
# terminal 1
prefect server start
# terminal 2 (from the project root)
prefect config set PREFECT_API_URL=http://127.0.0.1:4200/api
python dags/recommendation_flow.py
```
Prefect UI: http://127.0.0.1:4200

MLflow UI (from the project root): `mlflow ui --backend-store-uri sqlite:///mlflow.db` → http://127.0.0.1:5000

Single stage: `python run_pipeline.py --stage validate` (ingest, validate, prepare, transform, features, train, evaluate).
Tests: `python -m pytest tests`. No internet is needed: the data is generated by the code.

## Dataset
Clearly documented **synthetic data** (allowed by the assignment), generated in `src/ingestion/ingest.py` with a fixed seed (`seed: 42` in the config), so every run gives the same data.
- 1,000 users (age, country), 500 books (title, category from 8 categories, publish year, price)
- about 48,500 ratings (1–5) with unix timestamps between 2022-01-01 and 2024-12-31
- Each user has 1–2 favourite categories and rates 15–80 books; popular books and favourite categories are rated more often, and favourite categories get higher ratings.
- Because it is synthetic, the results show that the pipeline works, not how a real shop would behave.

## Demo errors
`configs/config.yaml` has `inject_demo_errors: true`, which adds 7 deliberately bad rows to the
interactions so the validation step can be demonstrated (the generated data is clean).
Set it to `false` to run on the untouched data.

## MLflow
Each model is one run in the experiment `recommendation-pipeline`: parameters (model type, dataset seed, sizes), artifacts (model file, feature catalog, results table) and metrics. Open it with the command above.

## Outputs
| File | Content |
|---|---|
| `reports/validation_report.md`, `validation_summary.csv` | validation results |
| `data/errors/bad_*.csv` | rejected rows with `error_reason` |
| `reports/feature_catalog.csv` | feature catalog |
| `data/features/*.csv` | user / item / interaction features |
| `reports/model_results.md`, `model_results.csv` | model comparison |

## Models
1. **Popularity baseline** – most-rated items the user has not seen.
2. **Item-based collaborative filtering** – cosine similarity between item rating vectors.

Metrics: Precision@10, Recall@10, NDCG@10, Coverage, Diversity (share of recommended pairs from different categories). K and the "liked" threshold are set in the config.
RMSE/MAE are not reported because both models produce rankings, not predicted ratings.
